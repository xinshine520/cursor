# 企业官网Rule文件：智谱大模型开放平台风格规范

**版本**：1.0  
**制定日期**：2024年12月  
**适用范围**：企业官网、产品页、开发者平台、品牌传播页

---

## 一、核心理念与目标

### 1.1 价值主张
- **核心定位**：「We don't just build models. We build decisions.」
- **第一性原理**：技术实力透明化、开发者体验优先、性能数据说话
- **用户心智**：塑造"技术可靠、响应迅速、生态开放"的专业AI平台形象

### 1.2 设计哲学
- **极简主义**：信息密度高但视觉噪音低，每像素服务于内容传递
- **计算美学**：用数据可视化、算法架构图、性能对比表替代装饰性元素
- **工程思维**：组件模块化、规则可量化、迭代可追踪

---

## 二、视觉设计规范

### 2.1 色彩系统
- **主色调**：深空蓝 (#0A0F1D) - 象征深度与专业
- **强调色**：科技蓝 (#2563EB) - CTA按钮、关键数据、活跃状态
- **辅助色**：极光紫 (#7C3AED) - 渐变过渡、特殊标签
- **功能色**：
  - 成功绿 (#10B981) - 部署状态、成功案例
  - 警告橙 (#F59E0B) - 限量提示、Beta功能
  - 中性灰 (#6B7280) - 次要文本、分割线
- **背景色**：纯白 (#FFFFFF) 与 极浅灰 (#F9FAFB) 交替
- **禁用纯黑色文本**：正文使用深灰 (#111827) 保证阅读舒适度

### 2.2 字体系统
- **标题字体**：Noto Sans SC Bold (字重700) / Inter Bold (英文)
  - H1: 48px/56px - 英雄区主标题
  - H2: 32px/40px - 板块标题
  - H3: 24px/32px - 卡片标题
- **正文字体**：Noto Sans SC Regular (字重400)
  - 正文: 16px/24px
  - 小字: 14px/20px (元数据、标签)
- **代码字体**：JetBrains Mono - 所有API示例、技术参数
- **禁用规则**：禁止出现任何衬线字体；禁止字体大小低于12px

### 2.3 布局网格
- **栅格系统**：12列，最大宽度1280px，左右边距24px
- **断点设置**：
  - 移动端：< 768px (单栏)
  - 平板：768px - 1024px (最多2栏)
  - 桌面：> 1024px (完整多栏)
- **垂直节奏**：基线8px，所有间距必须是8的倍数
- **卡片规格**：最小高度280px，圆角12px，阴影 `0 4px 6px -1px rgba(0,0,0,0.1)`

## 三、组件规范

### 3.1 导航栏
- **固定定位**：顶部悬浮，背景透明度95%，毛玻璃效果
- **左侧**：Logo + 产品名称（高度40px）
- **中间**：主导航菜单 (Products | Solutions | Developers | Pricing)
- **右侧**：
  - 搜索框（图标触发，非展开式）
  - 控制台按钮（Primary CTA）
  - 用户头像下拉菜单
- **滚动行为**：向下滚动时隐藏，向上滚动时浮现

### 3.2 英雄区 (Hero Section)
- **结构**：左侧文案 + 右侧可视化元素（模型架构图/性能仪表盘）
- **标题**：不超过15个汉字，必须包含核心性能数据（如"355B参数"、"SOTA性能"）
- **副标题**：一句话技术价值，禁用营销话术
- **CTA按钮**：
  - 主按钮："View Details" / "查看详情" (蓝色)
  - 次按钮："Technical Analysis" / "技术分析" (白色描边)
- **性能标签**：3-4个核心指标卡片，如推理速度、上下文长度、评测排名

### 3.3 模型卡片
- **强制元素**：
  - 模型名称 + 版本号（如GLM-4.6）
  - 性能徽章（SOTA、No.1等，仅限第三方评测）
  - 技术标签群（MoE、200K Context、Function Call）
  - 一句话能力描述
  - "View Details"链接（必须带箭头图标→）
- **数据展示**：使用"指标: 数值"格式，如`推理速度: 120 tokens/s`
- **图标系统**：每个模型类别使用固定单色图标（文字模型-📄，视觉模型-👁️，语音模型-🎤）

### 3.4 代码块
- **背景**：#1F2937 (深灰)
- **语法高亮**：使用VS Code Dark+主题配色
- **复制按钮**：右上角，点击后变为"已复制"状态
- **行号**：显示，颜色#9CA3AF
- **示例结构**：必须包含`import`、初始化、核心调用、输出注释

### 3.5 数据表格
- **表头**：背景#F3F4F6，文字加粗
- **斑马纹**：隔行背景#F9FAFB
- **对比列**：当前产品列使用蓝色背景#EFF6FF
- **移动端适配**：强制横向滚动，禁止换行

## 四、内容撰写规则

### 4.1 文案风格
- **禁用词汇**：「颠覆」「革命」「遥遥领先」「赋能」「一站式」
- **推荐词汇**：「SOTA」「benchmark」「efficiency」「optimization」「capability」
- **句式结构**：主动语态，动词开头，长度不超过20字
- **数据原则**：任何性能声明必须附带评测来源（如"MT-Bench"、"HumanEval"）

### 4.2 标题规范
- **H1**：产品名 + 核心参数（例：GLM-4.6 · 355B MoE Architecture）
- **H2**：功能 + 应用场景（例：Smart Agents for Real Needs）
- **H3**：具体能力（例：Universal Translation）

### 4.3 技术参数表达
- **数字格式**：使用千位分隔符 (355,000,000,000 parameters)
- **单位缩写**：B (billion), M (million), K (thousand), tokens/s
- **上下文长度**：统一用"200K context"格式
- **性能对比**：必须同时提供绝对值和百分比提升（例：+23% vs GLM-4.5）

### 4.4 多语言策略
- **默认状态**：标题/短句中英混合，长文案优先中文
- **专有名词**：SOTA、MoE、API、SDK保留英文
- **按钮文案**：必须双语并列（View Details 查看详情）
- **法律文本**：仅中文（服务条款、隐私政策）

## 五、交互与动效规范

### 5.1 按钮状态
- **默认**：背景#2563EB，文字白色，过渡200ms ease
- **悬停**：背景#1D4ED8，上浮2px，阴影加深
- **点击**：缩放95%，阴影消失
- **禁用**：背景#D1D5DB，光标not-allowed

### 5.2 页面动效
- **滚动Reveal**：元素进入视口上半部时触发，淡入+上移8px，时长300ms
- **数据动画**：数字从0递增到目标值，时长1.2s，easeOutQuart
- **Hover效果**：
  - 卡片：阴影`0 10px 15px -3px rgba(0,0,0,0.1)`，顶部蓝色进度条出现
  - 图片：轻微放大1.02倍
- **禁用**：任何旋转、弹跳、闪烁效果

### 5.3 加载状态
- **骨架屏**：使用灰色块模拟内容结构，禁止Spinner
- **进度指示**：API调用使用精确进度条（0-100%）
- **懒加载**：图片使用模糊到清晰的渐进加载

## 六、技术实现规范

### 6.1 性能基线
- **首次内容绘制 (FCP)**：< 1.5s
- **最大内容绘制 (LCP)**：< 2.5s
- **首次输入延迟 (FID)**：< 100ms
- **SEO评分**：Lighthouse > 95
- **无障碍评分**：aXe-core 0 violations

### 6.2 代码质量
- **框架**：Next.js 14+ (App Router) 或 Nuxt 3
- **样式**：Tailwind CSS 3.x，禁止使用内联style
- **TypeScript**：严格模式，any类型零容忍
- **组件拆分**：单个TSX文件不超过200行
- **命名规范**：PascalCase组件，camelCase函数，kebab-case CSS类

### 6.3 API集成
- **错误处理**：HTTP状态码 + 中文错误消息 + 追踪ID
- **速率限制**：在按钮旁显示剩余配额（如"今日可调用 8472/10000"）
- **响应格式**：统一包装`{code, message, data, traceId}`
- **重试机制**：失败自动重试3次，指数退避

### 6.4 SEO与元数据
- **Title**：产品名 + 核心参数 + 「- Zhipu AI Open Platform」
- **Description**：必须包含"API"、"pricing"、"SOTA"关键词，长度150-160字符
- **OG标签**：强制`og:image`指向1200x630的性能对比图
- **结构化数据**：TechArticle/SoftwareApplication Schema.org markup

## 七、品牌与合规规范

### 7.1 Logo使用
- **最小尺寸**：高度24px，周围留白等于x高度
- **背景**：仅允许白色、深空蓝或纯色背景，禁止纹理/图片
- **变体**：正式场合使用图文组合标，导航栏可仅用图标

### 7.2 数据合规
- **免责声明**：任何benchmark结果必须附带"Results may vary"脚注
- **用户数据**：不存储PII，日志脱敏在边缘层完成
- **GDPR/CCPA**：Footer必须包含"Do Not Sell My Personal Information"链接

### 7.3 法律文本
- **服务条款**：使用GitHub风格版本控制，显示最后更新日期
- **隐私政策**：分层展示，"摘要+完整版"结构
- **Cookie**：仅使用必要类别，禁用营销追踪Cookie

---

## 八、内容运营规则

### 8.1 更新频率
- **模型发布**：重大版本更新必须在72小时内上线
- **性能数据**：基准测试结果每月更新
- **博客**：技术深度文章每周至少1篇
- **Changelog**：产品变更实时更新，聚合在`/changelog`

### 8.2 社区内容
- **GitHub链接**：所有开源项目必须star数显示实时
- **开发者案例**：必须包含头像、姓名、所属公司、可验证数据
- **技术博客**：作者必须有Zhipu认证标识，禁用客座文章

### 8.3 危机处理
- **服务降级**：在导航栏显示状态灯（绿/黄/红）
- **事故公告**：使用固定横幅，背景#FEF3C7，文字#92400E
- **Twitter同步**：每次status更新必须同步到X平台
